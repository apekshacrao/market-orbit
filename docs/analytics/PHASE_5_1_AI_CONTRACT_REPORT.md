## 3. Final Recommendation and Evidence Schema

### 3.1 Controlled Vocabularies

```python
class RecommendationCategory(str, Enum):
    BUDGET_ALLOCATION = "budget_allocation"
    CREATIVE_OPTIMIZATION = "creative_optimization"
    CHANNEL_SCALING = "channel_scaling"
    WASTE_REDUCTION = "waste_reduction"
    DATA_TRACKING = "data_tracking"


class RecommendationSource(str, Enum):
    GROQ_LLM = "groq_llm"
    DETERMINISTIC_FALLBACK = "deterministic_fallback"
```

> [!IMPORTANT]
> The `source` attribute strictly enforces attribution honesty: recommendations must never be labeled `groq_llm` unless generated by real LLM inference. Mock recommendations and deterministic rules are labeled `deterministic_fallback`.

### 3.2 Supporting Evidence (`SupportingEvidence`)

Represents verifiable observations grounded in actual observed data:

| Field | Type | Required | Description |
|---|---|---|---|
| `metric` | `str` | Yes | Primary metric under observation (e.g. `roas`, `cpa`, `conversions`, `spend`). Stripped and lowercased. |
| `observed_value` | `Optional[float]` | No | Empirical metric value observed. Must be finite (no NaN/Inf). |
| `campaign_name` | `Optional[str]` | No | Associated campaign identifier if applicable. |
| `dimension` | `Optional[str]` | No | Dimension identifier (e.g., `device`, `location`, `customer_segment`). |
| `dimension_value` | `Optional[str]` | No | Specific slice value within dimension (e.g., `Mobile`, `CA`). |
| `benchmark_value` | `Optional[float]` | No | Optional baseline/target value. Must be finite; never fabricated. |
| `context` | `Optional[Dict[str, Any]]` | No | Additional verifiable metric key-values (e.g., `{"spend": 450.0, "conversions": 12}`). |

### 3.3 Recommendation Item (`RecommendationItem`)

The core recommendation entity:

| Field | Type | Required | Description |
|---|---|---|---|
| `id` | `str` | Yes | Unique or deterministic identifier (e.g. `rec-001`). Cannot be empty. |
| `category` | `RecommendationCategory` | Yes | One of the 5 controlled categories. |
| `title` | `str` | Yes | Concise plain-language title. Non-empty string. |
| `action` | `str` | Yes | Specific actionable directive. Non-empty string. |
| `rationale` | `str` | Yes | Empirical explanation justifying the action. Non-empty string. |
| `supporting_evidence` | `Optional[Union[SupportingEvidence, List[SupportingEvidence]]]` | No | Verifiable observation(s) or `None`. |
| `limitations` | `List[str]` | No | Known constraints/risks. Defaults to `[]`. Rejects non-strings/empty strings. |
| `source` | `RecommendationSource` | Yes | `groq_llm` or `deterministic_fallback`. |
| `description` | `Optional[str]` | No | Synced automatically with `rationale` for full backward compatibility. |

### 3.4 Container Model (`RecommendationBatch` / `RecommendationResponse`)

Provides container-level management and serialization:

| Field / Method | Type | Description |
|---|---|---|
| `recommendations` | `List[RecommendationItem]` | List of validated recommendation objects (defaults to `[]`). |
| `dataset_id` | `Optional[str]` | Dataset identifier. |
| `generated_at` | `Optional[str]` | ISO timestamp of generation. |
| `to_list()` | Method | Exports a JSON-serializable list of dictionary payloads. |
| `to_json()` | Method | Serializes the container directly to a standard JSON string. |
| `from_list()` | Classmethod | Adapts and normalizes a raw list of dictionaries into a validated batch. |

## 4. Validation and Serialization Rules

1. **Non-Finite Number Rejection**:
   - `math.isnan()` and `math.isinf()` are explicitly checked on `observed_value`, `benchmark_value`, and within `context` dictionary values.
   - Any NaN, positive Infinity, or negative Infinity raises a `ValidationError`.
2. **Missing Optional Values**:
   - Optional fields remain `None` when omitted.
   - No synthetic values, assumptions, or imaginary benchmarks are fabricated.
3. **String Sanitization**:
   - Required string fields (`id`, `title`, `action`, `rationale`) are validated to ensure they are non-empty and non-whitespace.
   - Categories and sources accept case-insensitive and snake_case/hyphen variations before coercing to valid enums.
4. **Clean JSON Serialization**:
   - All models support Pydantic V2 `.model_dump(mode="json")` and `.model_dump_json()`.
   - String enums serialize directly to lowercase strings (`"budget_allocation"`, `"groq_llm"`), avoiding object wrapper leaks.

---

## 5. Backward Compatibility Decisions

1. **Dual Representation (`rationale` and `description`)**:
   - Existing frontend components and legacy consumers expect `item["description"]`.
   - The contract defines `rationale` as the formal analytical field and automatically populates `description` from `rationale` via a model post-validator.
   - Existing callers reading `item.get("description")` or `item.get("rationale")` both receive consistent data.
2. **Normalization Adapter (`normalize_recommendation`)**:
   - Legacy records currently stored in PostgreSQL `AnalysisResult.ai_recommendations` contain `{"title", "description", "action"}` without `id`, `category`, `source`, or `supporting_evidence`.
   - `normalize_recommendation()` automatically converts legacy dictionaries into valid `RecommendationItem` instances:
     - Infers category heuristically from title and action keywords.
     - Maps `description` to `rationale`.
     - Assigns `source = RecommendationSource.DETERMINISTIC_FALLBACK` (honestly reflecting non-LLM origin).
     - Leaves `supporting_evidence = None` and `limitations = []` without inventing fake data.
3. **Database & API Stability**:
   - No database schema migrations or column modifications were performed.
   - `AnalysisResultResponse` in `backend/app/schemas/result.py` continues to accept `recommendations: List[Dict[str, Any]]` seamlessly via `RecommendationBatch.to_list()`.
